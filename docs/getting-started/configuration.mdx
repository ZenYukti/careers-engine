Before running Careers Engine, a few project components must be configured.

The platform is designed around two repositories:

- **careers-engine** contains the discovery, processing, and publishing logic.
- **careers-data** stores job records, destination-specific publication history, and queued opportunities.

Together, these repositories provide a reproducible and version-controlled workflow for discovering and publishing software engineering opportunities.

---

## Repository layout

Clone both repositories into the same workspace.

```bash
workspace/
├── careers-engine/
└── careers-data/
```

Clone the companion repository.

```bash
git clone https://github.com/ZenYukti/careers-data.git
```

<Info>
`careers-data` acts as the persistent storage layer for Careers Engine. Discovery and publishing workflows read from or update this repository.
</Info>

---

## Environment variables

Create a `.env` file in the project root.

```text
careers-engine/
├── .env
├── src/
├── scripts/
└── ...
```

Configure the environment variables required for publishing and persistent storage.

```env
DISCORD_TOKEN=...
DISCORD_CHANNEL_ID=...
DISCORD_GUILD_ID=...

TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...

DATA_DIR=../careers-data
```

<Card type="warning" title="Single Server Deployment">
`DISCORD_GUILD_ID` restricts the bot to a single Discord server. If the bot joins another server, it automatically leaves and publishes opportunities only to the configured guild.
</Card>

Additional variables may be required depending on the workflow being executed.

---

## Workspace structure

After configuration, your workspace should resemble:

```text
workspace/
├── careers-engine/
│   ├── .env
│   ├── docs/
│   ├── scripts/
│   └── src/
│
└── careers-data/
    ├── jobs.json
    ├── queue.json
    └── delivery-history/
        ├── discord.json
        └── telegram.json
```
